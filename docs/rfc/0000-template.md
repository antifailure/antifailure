## What this changes

One paragraph. What a user or a provider author will be able to do that they
cannot do today, or will have to do differently. If nothing outside this
repository changes, this does not need an RFC.

## Why now

The problem, with the evidence that it is a problem: an error somebody hit, a
guarantee that cannot be kept, a provider that cannot be written against the
current interface. A proposal whose motivation is that the current design is
untidy is a refactor, not an RFC.

## The design

Enough that somebody else could build it. Interface signatures where an
interface changes, the manifest keys where the manifest changes, the events
where the stream changes.

## What it costs

What becomes harder, what has to be migrated, what a user has to do on upgrade,
and what this commits the project to that it is not committed to today.

## Alternatives

For each: what it was, and the specific reason it is not this. An alternative
with no stated reason for losing is a list item, not an alternative.

## Open questions

The things you do not know yet, named. An RFC with none is either finished or
not looking hard enough.
