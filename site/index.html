  • Fail closed. Unknown egress, missing sanitization, or failed cleanup blocks the ship.
  • Customer boundary. Production data stays in the customer cloud. The twin never leaves that trust boundary.
  • Pass, warning, or block. The output is an evidence-backed gate on the pull request, not a preview URL alone.
  • Cleanup is a safety property. Resources are journaled before create and compensated on teardown.
  • AI discovers, systems prove. Crowdi explores. Deterministic scenarios and the oracle decide.
  • Postgres wedge. Start with schema migrations on real volume, then expand the twin.
→Trust model
Fail closed. Customer-hosted. Production data stays in your boundary. Cleanup is a first-class safety property, not a best-effort script.
  • Fail closed
    Unknown destinations, missing sanitization evidence, or failed cleanup cannot ship.
  • Customer-hosted
    Production data stays inside the customer boundary. The control plane never needs a copy.
→What we will not claim
Zero rollback. No deployment can ever fail. Thousands of AI agents behave exactly like humans. One click perfectly clones every cloud. Use measurable evidence instead.
