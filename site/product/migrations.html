The report is causal. Change, lock, workflow, evidence, then the decision.

Staging with a handful of rows will not show an exclusive lock, a table rewrite, or the moment old binaries fail to read new rows. The twin runs the migration the way production would — then attaches the finding to the pull request.

Add the nullable column without a default, backfill in batches, deploy dual-read compatibility, then enforce the constraint in a later migration.

Failures conventional tests miss. The engine measures what staging cannot.

  • Locks

    Acquisition, duration, blocked statements, and cumulative blocked time.

  • Rewrites

    Full table rewrites, index builds, constraint failures on rare rows.

  • Plans

    Query-plan changes and latency distributions under production-shaped data.

  • Pools

    Connection-pool pressure, CPU, memory, IOPS, disk, and WAL growth.

  • Coexistence

    Old and new application versions during a rolling deploy.

  • Rollback

    Whether candidate writes make rolling rollback unsafe.

Safer pattern: expand-and-contract. Evidence, then a recommended path that keeps checkout live.

Switch the film to expand-and-contract. Lock drops to 0.4s, blocked statements stay at zero, checkout p99 holds near 830ms, and rollback stays feasible.

    Expand

  2. 02

    Backfill

    Fill values in batches so checkout never waits on ACCESS EXCLUSIVE.

    Dual-read

    Deploy code that reads both shapes before you tighten the schema.
