# fixed

A workflow whose expectation could never match named it where nobody reads.

An expectation that carries no word the matcher can look for can neither pass
nor fail, and the run says so. It said so at character 295 of a 489 character
sentence, and the report's table cell stops at 120, so the half that named WHICH
expectation was at fault reached nobody reading the row. It survived only on the
`Got:` line inside the folded details block, which is where somebody looks once
they already suspect something.

The sentence that did lead the cell was worse than incomplete. It said nothing
on this page moves the workflow forward, about a page that may be showing
exactly what was asked for, so it pointed the reader at their application when
the fault was in their manifest. A diagnostic that is merely truncated costs a
click. One that points the wrong way costs an afternoon.

The cell now opens with the quoted expectation, then what is wrong with it, then
the two ways to write it so it can be checked. The name leads the sentence
rather than closing it, so a long expectation is named in full rather than cut
off halfway through. Everything that was said before is still said, in the same
details block, for anyone who opens it.

Only an expectation that could never be met earns the front of the cell. One
that simply was not met is a different fact and reads exactly as it did.
