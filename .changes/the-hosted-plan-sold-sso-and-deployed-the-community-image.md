# fixed

The hosted control plane now runs the enterprise edition, so single sign-on,
directory provisioning and audit streaming exist where the hosted enterprise
plan sells them.

Until this release, continuous deployment built and deployed the community
image to both hosted environments. Its entry point mounts none of the three, so
every identity provider callback and every SCIM request answered 404, and
nothing said so: a community control plane is ready on the right commit and
passes every health check. The enterprise image was built and proven on every
pull request and deployed nowhere.

Deployment now builds `control-plane-enterprise`, and two checks stand either
side of it. Before the image moves, the app must carry the four variables the
enterprise entry point needs, because without the single sign-on sealing key
that process exits before it listens; an environment missing any of them is
refused with the app untouched. After traffic moves, the public origin must
answer a SCIM discovery request with 200 and a sign-in discovery request with
400, so a deploy that is healthy and serves the wrong edition, or a licence
that does not permit a feature, fails the release instead of passing it.

The sealing key is generated by Terraform into the environment's vault, and the
licence is issued with `tools/licensegen` and placed by a person. The production
guide has the one-time procedure under Turning on the enterprise edition. The
hosted signing key's location, and who can read it, is recorded on the issuing
page as a measured limit.
