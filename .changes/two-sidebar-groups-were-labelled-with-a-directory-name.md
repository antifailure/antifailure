# fixed

Two sidebar groups were labelled with a raw lowercase directory name.

`schemas` and `runbooks` sat among nine sentence-case labels, and the second
contained a page whose own title was "Runbooks", so one thing was named twice in
two casings. Vir asked why the documentation did not look like the rest of the
site; this is one of the places it did not.

`autogenerate` cannot fix it. It labels a nested group with the directory name
and offers no override: Starlight's `navigation.ts:334` is literally
`label: dirName`. Renaming the directories is not available either, because a
page's URL is its path under `src/content/docs` exactly, every engine error
links to one, and `tools/errcheck` refuses to build if any of those stops
resolving. A directory name also cannot contain a space, so no directory will
ever produce a sentence-case label.

So Reference and Self-hosting are listed by hand and the other seven groups are
still autogenerated. The groups read "Generated schemas" and "Runbooks" now, and
the runbook index is "Which alert is which" rather than repeating the name of
the group it sits in.

A hand-written list is the thing that rots, so `just sidebarcheck` gained a
fourth rule: every page is in the sidebar exactly once, by an `autogenerate`
directory that contains it or by its own slug, never both and never neither. Add
a page under either directory and the gate says so. Five cases were watched
failing: a page dropped from the list, a page listed twice, a slug naming no
page, a new page nobody added, and the sidebar block itself being renamed, which
would otherwise have made the whole rule pass over nothing.

The first version of that rule produced a false finding, which is worth
recording because it is the third instance of one shape tonight. It read the
`autogenerate: { directory: "self-hosting/runbooks" }` value as an explicit page
slug, since that is also a quoted string with a slash in it, and reported the
runbooks index as listed twice. A gate that cries wolf once is a gate somebody
turns off.
