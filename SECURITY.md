# Security policy

Antifailure handles the most sensitive thing a team owns: a copy of production
data. We treat every report seriously and we would rather hear about a
suspicion than miss a real problem.

## Reporting a vulnerability

Email **security@antifailure.dev**. Please do not open a public issue for a
security problem; the issue templates redirect security reports to this address
and the triage workflow closes them automatically with a pointer here.

Include, as far as you can:

* the component (engine, sidecar proxy, masking, runner, control plane, infrastructure)
* the version, from `af version`
* what an attacker gains
* a reproduction, ideally a failing test or a short script
* whether the finding is already public

If you would like to encrypt the report, ask for a key in a first message with
no details and we will reply with one.

## What we commit to

| Stage | Target |
| --- | --- |
| Acknowledgement | 72 hours |
| Initial assessment with a severity | 5 business days |
| Fix or documented mitigation for critical and high findings | 30 days |
| Public advisory after a fix ships | 7 days |

We will keep you updated at least weekly while a report is open, credit you in
the advisory unless you prefer otherwise, and tell you before we publish.

## Supported versions

The latest minor release of the current major line receives security fixes.
While the project is pre-1.0, that means the latest release.

## Scope

In scope: the engine and CLI, the sidecar proxy and policy engine, the masking
and verification pipeline, the agent runner, the control plane, the published
container images, the release artifacts and installer, and the Terraform and
Helm assets in this repository.

Out of scope: findings that require a compromised workstation or an attacker
who already holds the operator's cloud credentials, denial of service through
sheer volume against a self-hosted instance the reporter controls, and reports
generated by a scanner with no demonstrated impact.

## Our own controls

Secret scanning runs on the full history with two scanners on every push.
Dependencies are pinned, license-checked, and vulnerability-scanned in CI.
Release artifacts are reproducible, carry an SBOM, and are signed with cosign
keyless signing. The adversarial test suite in `tests/adversarial` tries to
escape the environment sandbox, bypass the proxy, and exfiltrate secrets on
every run. Details are in the security section of the documentation.

## Incident history

Recorded in `docs/security/incidents/`. An empty directory means there has not
been one.
